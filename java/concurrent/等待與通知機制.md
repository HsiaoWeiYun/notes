### 等待與通知機制

一個thread修改了一個物件的數值, 而另一個thread感知到了變化而進行對應的操作, 前者是生產者, 後者是消費者. <br>

<br> 在java中該如何處理呢?

最簡單的做法就是讓while迴圈一直檢查條件, 不滿足就跳出迴圈做消費者改做的事情.

```java

private boolean available = false;

while(!available){
    Thread.sleep(1000);    
}
doSomeThing();
```
但是這樣做有幾個缺點
1. 缺乏即時性: 如果睡得太久沒辦法馬上感知到資源異動
2. 難以降低開銷: 如果睡的短了會消耗更多的cpu資源

java的等待、通知機制可以解決這個矛盾並實現所需的功能. <br>
等待/通知的方法是所有java object都具備的, 因為他被定義在java.lang.Object上

| 名稱              | 描述                                                                    |
|-----------------|-----------------------------------------------------------------------|
| notify()        | 通知等待的thread, 使其從wait()方法返回, 而返回的前提是thread獲取了物件的鎖                      |
| notifyAll()     | 通知所有在該物件上等待的thread                                                    |
| wait()          | 使呼叫此方法的thread進入waiting狀態, 只有其他thread**通知**或**中斷**才會返回 (呼叫wait()後會釋放鎖) |
| wait(long)      | 等待一段時間, 超時自動返回 (仍需競爭鎖)                                                |
| wait(long, int) | 對超時時間有更細力度的控制, 可達到納秒                                                  |

* 等待通知機制: 指的是thread A呼叫物件Q的wait()方法進入等待狀態後, 而thread B呼叫物件Q的notify/notifyAll方法, thread A收到通知後從wait()方法返回, 繼續後續操作. <br>
              wait/notify、notifyAll就像開關信號一樣, 用來完成等待方與通知方之間的交互工作.

舉例
```java
public class ProducerConsumerExample {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();
        
        Thread producer = new Thread(new Producer(resource));
        Thread consumer = new Thread(new Consumer(resource));
        
        producer.start();
        consumer.start();
    }
}

class SharedResource {
    private int data;
    private boolean available = false;
    
    public synchronized int get() {
        while (!available) {
            try {
                wait();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        available = false;
        notifyAll();
        return data;
    }
    
    public synchronized void put(int value) {
        while (available) {
            try {
                wait();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        data = value;
        available = true;
        notifyAll();
    }
}

class Producer implements Runnable {
    private SharedResource resource;
    
    public Producer(SharedResource resource) {
        this.resource = resource;
    }
    
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            resource.put(i);
            System.out.println("Producer produced: " + i);
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
}

class Consumer implements Runnable {
    private SharedResource resource;
    
    public Consumer(SharedResource resource) {
        this.resource = resource;
    }
    
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            int value = resource.get();
            System.out.println("Consumer consumed: " + value);
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
}
```
ps. available 變數不需要被宣告為volatile, 因為synchronized已經確保記憶體可見性以及操作原子性

說明:
1. 使用wait()、notify()、notifyAll()時需要先取得**監視器鎖**
2. 呼叫wait()後thread狀態從running變為waiting, 並且把當前thread放置監視器內的**等待列隊**
3. 呼叫notify()、notifyAll()後thread並不會馬上從wait()返回, 等到呼叫notify的thread釋放鎖後呼叫wait()的thread才有機會返回 (也還要競爭鎖),
4. notify()方法將檢視器內**等待列隊**中的一個thread移到**同步列隊**中, notifyAll()則是把等待列隊中的全部thread都移入同步列隊中, 被移動的thread狀態從WAITING變為BLOCKED

從上面的範例可以觀察到, wait/notify 生產者消費者可以歸納出一種公式
1. 獲取監視器鎖
2. while 迴圈條件判斷, 如果條件滿足就呼叫wait()等待
3. 條件不滿足就執行對應業務, 並呼叫notifyAll 喚醒等待的thread
